# Code Review

全面的 AI 代码审查 Skill：分析 git diff，检查 SOLID 原则，扫描代码质量与安全，检测死代码，验证最佳实践。问题按 P0-P3 优先级分类，附带合并建议（APPROVE / REQUEST_CHANGES / COMMENT）。默认仅审查不改代码，确认后再修复。支持前后端。

## 安装

```bash
npx skills add lenslp/skills --path code-review
```

## 检查项

| 类别 | 检查内容 |
|------|---------|
| **SOLID & 架构** | SRP/OCP/LSP/ISP/DIP 违规、代码异味、重构建议 |
| **代码质量** | 正确性、边界条件、可读性、类型安全、API 设计 |
| **安全** | 注入攻击、认证授权、数据泄露、输入验证、依赖 CVE、前端安全 |
| **死代码** | 未使用/冗余代码、清理计划（立即删除 vs 延迟迁移） |
| **最佳实践** | 架构、错误处理、测试、性能 |
| **前端** | 组件设计、渲染性能、状态管理、可访问性、包体积、UX 健壮性 |

## 优先级

| 优先级 | 定义 | 处理方式 |
|--------|------|---------|
| **P0** | 安全漏洞、数据丢失、崩溃 | 必须立即修复 |
| **P1** | 逻辑错误、缺少错误处理、契约破坏 | 合并前修复 |
| **P2** | 代码质量、可读性、测试覆盖不足 | 应该修复 |
| **P3** | 风格规范、命名、小优化 | 可选改进 |

## 工作流

```
git diff → 评估范围 → SOLID → 质量 → 安全 → 死代码 → 最佳实践 → 前端 → 报告 → 裁定 → 确认
```

1. **分析 Diff** — 运行 `git diff --stat`，评估范围，生成汇总表
2. **分批策略** — 超过 500 行按模块拆分，逐批审查
3. **SOLID & 架构** — 检查 SRP/OCP/LSP/ISP/DIP，标记代码异味
4. **代码质量** — 正确性、边界条件、可读性、类型安全
5. **安全扫描** — 注入、认证、数据泄露、前端安全、语言专项
6. **死代码** — 识别清理候选（立即删除 vs 延迟迁移）
7. **最佳实践** — 架构、错误处理、测试、性能
8. **前端扫描** — 组件设计、状态、a11y、包体积、UX（自动检测）
9. **报告** — 所有问题按 P0-P3 表格输出 + 合并裁定
10. **交互修复** — 用户选择修复范围（确认前不改代码）

## 合并裁定

| 裁定 | 条件 |
|------|------|
| ✅ **APPROVE** | 无 P0 或 P1 问题 |
| ⚠️ **REQUEST_CHANGES** | 存在 P0 或 P1 问题 |
| 💬 **COMMENT** | 无问题，或仅有信息性观察 |

## 在 Cursor 中使用

安装后 skill 会自动注册，在 Cursor Chat（Agent 模式）中直接使用。

### 自动触发

当提问包含以下关键词时自动激活：

- "帮我 review"
- "review my code"
- "检查代码质量"
- "安全扫描"

### 手动触发

示例提问：

```
帮我 review 一下最近的代码改动
```

```
对比 main 分支，review 当前分支的变更
```

```
检查一下我 staged 的代码有没有安全问题
```

### Review 完成后

报告按 P0-P3 优先级列出所有问题并附带合并裁定，然后选择修复方式：

- 按优先级：`fix P0`、`fix P0 and P1`
- 按模块：`fix src/auth/`
- 按编号：`fix #1, #3, #5`
- 全部修复：`fix all`
- 跳过：`skip`
